# 安全模型

## 它保护什么

1. **越权改配置**：只有到达对应等级才能改对应范围的配置；受保护的两个插件永远不能碰。
2. **越权改人格**：L2 起才允许，改前自动备份，失败回滚。
3. **误改主配置**：L3 只能动两个展示类键（`wake_prefix`、`reply_prefix`），且每次要一次性批条。
4. **事故可收敛**：主人可 `/提权 事故` 扣分降级，或 `/提权 重置` 清零等级。

## 它不保护什么

**这不是沙箱。** 设计上就是一个「诚实但可能犯错」的 AI 的自律工具：

- 拥有插件目录写权限的进程，可以改代码、读数据、绕过考核；
- 红线关键词是启发式匹配，改名、编码、间接调用都能绕开；
- `gate.json` 是普通文件，主人或任何有写权限的进程都能手改；
- AstrBot 管理员本身即最高权限，本插件不改变这一点。

真正的边界应该由部署层提供：

- 容器隔离与只读挂载；
- 独立的系统用户运行 AstrBot；
- 文件系统 ACL，限制插件目录的写入者；
- 定期快照与异地备份。

## 威胁模型

| 威胁 | 是否覆盖 | 说明 |
| --- | --- | --- |
| AI 手滑改错配置 | ✅ | 备份 + 还原 + 等级限制 |
| AI 恶意篡改考核分 | ❌ | 有文件写权限即可绕过 |
| AI 读走密钥 | ❌ | 应靠文件权限与密钥管理 |
| 主人误操作 | 部分 | 备份可回滚 |
| 第三方插件伪造工坊账本 | ❌ | 默认信任同进程插件 |

## 部署加固清单

- [ ] 用容器运行 AstrBot，只映射必要端口；
- [ ] 把 `data/plugin_data/astrbot_plugin_moon_gate/` 与工坊目录纳入每日备份；
- [ ] 不要给 AI 的插件进程 root 或宿主目录写权限；
- [ ] 定期抽查 `gate.json` 的 `events` 与工坊 `events.jsonl` 是否对得上；
- [ ] 密钥使用环境变量注入，不写进 `cmd_config.json`；
- [ ] 生产环境把 `l3_days` 调高，或直接关闭 L3 的 `cmd_config` 通道。
